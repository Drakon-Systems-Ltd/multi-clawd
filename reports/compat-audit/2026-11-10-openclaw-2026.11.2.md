# Compatibility audit: multi-clawd v2.6.6 vs OpenClaw v2026.11.2 and v2026.10.10

Issue #146. Bounded audit of `origin/master` at 340adc4 (v2.6.6 plus #150) against the current OpenClaw stable and the previous minor. Observed on 2026-11-10 (UTC), 12:08 to 12:40.

## Scope and method

- **Audited:** `@drakon-systems/multi-clawd` at 340adc4, built from source, plus the published 2.6.6 through `npx`.
- **Against:** OpenClaw **2026.11.2** (npm `latest`, live-checked 2026-11-10: `latest` 2026.11.2, `beta` 2026.11.5-beta.1, `extended-stable` 2026.9.36), **2026.11.1** and **2026.10.10** (previous minor). Sources: the three published npm packages installed into scratch prefixes, and the tagged GitHub sources (`v2026.11.2` b556fdf, `v2026.11.1` 4ffdd20, `v2026.10.10` 7dc3350). Control: the pinned build SDK 2026.8.1.
- **Claude CLI:** registry `latest` 2.1.322, `stable` 2.1.311 (live-checked). Only `--version` and `--help` were run, under a scratch `HOME`.
- **Isolation:** every executed check used a scratch `HOME`, `OPENCLAW_STATE_DIR`, `OPENCLAW_CONFIG_PATH` and npm cache, an empty environment (`env -i`), a gateway port nothing listens on, and fixture accounts whose "credentials" are placeholder strings. No real credential was read, printed or copied. No provider call was made. No gateway was installed, updated, started or restarted. No release was cut. `package.json` and `package-lock.json` are unchanged (the 2026.11.2 overlay used `npm install --no-save`).
- **Evidence labels:** **REAL** = the published OpenClaw package's own code was executed (CLI or an in-process call) in the isolated state. **STATIC** = read from source or from the dist by shape. **FIXTURE** = a test in this repository. **UNTESTED** = not established.
- **Out of scope here:** #155 (automation account binding) and #151/#152 (shim lock lease) are owned elsewhere and are not re-examined. One further finding is handled through the private channel described in `SECURITY.md` and is not described in this report.

One probe side effect to record: the control case of the manual-compaction probe (the bundled `claude-cli` backend) got far enough to try to start `claude`. The scratch `PATH` held no `claude`, so the attempt failed with "not found" and nothing ran.

## Findings

### 1. Manual `/compact` is refused on pooled backends (BROKEN, pre-existing, filed #159)

`buildBackend` declares `ownsNativeCompaction: true` and no `manualCompaction`. Core's manual-compaction path returns a failure result for exactly that pair, before any process starts:

```
CLI backend "clawd" owns compaction but does not support manual compaction.
```

Source: `src/agents/embedded-agent-runner/compact.ts` lines 69 to 75, identical at `v2026.10.10`, `v2026.11.1` and `v2026.11.2` (https://github.com/openclaw/openclaw/blob/v2026.11.2/src/agents/embedded-agent-runner/compact.ts#L69-L75). The bundled backend declares the contract (https://github.com/openclaw/openclaw/blob/v2026.11.2/extensions/anthropic/cli-backend.ts#L209-L210), and the contract is public SDK surface (https://github.com/openclaw/openclaw/blob/v2026.11.2/src/plugins/cli-backend.types.ts#L572-L583). Unlike #137, the plugin can implement it.

REAL evidence. The published packages' own `compactNativeCliSession` was called in-process, after OpenClaw's own plugin registry had loaded the plugin from source, in the isolated state:

| OpenClaw | `clawd` | `claw1` | control `claude-cli` | control unknown id |
|---|---|---|---|---|
| 2026.11.2 | refused | refused | passes the gate | `undefined` (core's own compaction) |
| 2026.11.1 | refused | refused | passes the gate | `undefined` |
| 2026.10.10 | refused | refused | passes the gate | `undefined` |

Not a 2026.11.2 regression. 2026.8.1 carries the same refusal text in its dist (STATIC, not exercised). A live `/compact` from a chat surface against a running gateway is UNTESTED. The previous audit (#133) listed `manualCompaction` among fields that are "graceful when missing"; that holds for automatic compaction and is wrong for the manual command.

FIXTURE: `tests/issue-146-manual-compaction-contract.test.ts` pins the host gate by shape, the bundled declaration and the pool's current declaration. It passes against 2026.8.1, 2026.10.10, 2026.11.1 and 2026.11.2 (`MULTI_CLAWD_OPENCLAW_DIST`), and its last assertion is the one to flip when #159 is implemented. It fixes nothing.

Regression scope for the fix is in #159: mirror the three contract members, keep the control run on the account that holds the native session, keep it out of served-turn accounting, and compare the pool's argv for `controlOperation: "compact"` with the bundled resolver's, which changed in 2026.11.2.

### 2. What changed in 2026.11.2 on the surfaces the plugin mirrors (no break measured)

Between `v2026.11.1` and `v2026.11.2` (959 files changed), the files the plugin depends on changed as follows.

- `src/plugins/cli-backend.types.ts`: `CliBackendResolveExecutionArgsContext` gains optional `agentId` and `controlOperation?: "compact"`. `src/agents/cli-runner/execute.ts` now passes both. Additive; `resolvePoolExecutionArgs` ignores unknown fields.
- `extensions/anthropic/cli-shared.ts`: the bundled backend moved its argument normalisation from `normalizeConfig` (registration time) to `resolveExecutionArgs` (launch time). The pool does not call the bundled normaliser, so nothing breaks; the pool's resolver keeps its own port of the host-owned and side-question steps, and the 31 tests covering those pass on the 2026.11.2 SDK.
- `extensions/anthropic/provider-discovery.ts` and `src/agents/model-auth-availability.cli-runtime.ts`: the bundled provider's synthetic auth now carries `nativeAuth`, and the evaluator accepts an object runtime-auth mode. That branch sits after the early return for a provider that is its own CLI runtime, which is the pool's case, so the pool's `oauth:` marker path is unchanged (STATIC). `src/agents/model-auth-runtime-shared.ts` adds `assertProviderAuthSupportsHttp`, which refuses credentials carrying `nativeAuth`; the pool's results carry none and its own `prepareRuntimeAuth` guard still refuses the marker (FIXTURE, `tests/runtime-auth-wiring.test.ts`, 10 pass).
- `src/agents/model-catalog-view.ts`: implicit native runtime selection narrowed to `runtime === "auto"`, and harness evidence is now keyed on the credential source. The plugin registers no agent harness and its catalog rows carry no native runtime, so the host evaluation is returned unchanged (STATIC).
- `src/agents/cli-runner/prepare.ts` and `src/gateway/mcp-grant-store.ts`: loopback MCP grant cleanup. Internal to core; no plugin surface.
- `extensions/anthropic/openclaw.plugin.json`: byte-identical to 2026.11.1, so the manifest mirror (#134) needs no new fixture.

### 3. Auth readiness reads "indeterminate" without a gateway, on every audited version (not a regression)

With the fixture default model routed at the pool, `openclaw models status --json` reports `modelRouteIssues` of kind `indeterminate` ("Auth readiness could not be confirmed") for the pool and both accounts, with `missingProvidersInUse: []`, on 2026.10.10, 2026.11.1 and 2026.11.2 alike. The one-shot CLI has no warmed login verdict, which is the documented behaviour of the synchronous hook. Nothing here distinguishes the versions. The gateway-backed state that the Control UI picker reads was not started and stays UNTESTED.

### 4. Test fragility observed once (no issue filed)

`tests/issue-137-isolated-completion-contract.test.ts` reads every `.js`/`.mjs` file in the installed dist to find one sentence. The 2026.11.2 dist has 9,104 such files (5,852 in 2026.8.1). On a cold page cache at idle I/O priority the first test took 7.5 s and hit the 5 s default timeout; the immediate re-run passed. CI runs that suite only against 2026.8.1 today, so this has not been seen there. If the suite is ever added to the SDK overlay lane, narrow the file scan or raise the timeout. The new test in this change reads only the compaction chunks for that reason.
