# Compatibility audit: multi-clawd v2.6.6 vs OpenClaw v2026.11.2 and v2026.10.10

Issue #146. Bounded audit of `origin/master` at 340adc4 (v2.6.6 plus #150) against the current OpenClaw stable and the previous minor. Observed on 2026-11-10 (UTC), 12:08 to 13:29.

## Scope and method

- **Audited:** `@drakon-systems/multi-clawd` at 340adc4, built from source, plus the published 2.6.6 through `npx`.
- **Against:** OpenClaw **2026.11.2** (npm `latest`, live-checked 2026-11-10: `latest` 2026.11.2, `beta` 2026.11.5-beta.1, `extended-stable` 2026.9.36), **2026.11.1** and **2026.10.10** (previous minor). Sources: the three published npm packages installed into scratch prefixes, and a clone of the public repository at the three tags (`git log -1` on each: `v2026.11.2` b556fdf, `v2026.11.1` 4ffdd20, `v2026.10.10` 7dc3350). Control: the pinned build SDK 2026.8.1.
- **Claude CLI:** registry `latest` 2.1.322, `stable` 2.1.311 (live-checked). Only `--version` and `--help` were run, under a scratch `HOME`.
- **Isolation:** every executed check used a scratch `HOME`, `OPENCLAW_STATE_DIR`, `OPENCLAW_CONFIG_PATH` and npm cache, an empty environment (`env -i`), a gateway port nothing listens on, and fixture accounts whose "credentials" are placeholder strings. No real credential was read, printed or copied. No provider call was made. No gateway was installed, updated, started or restarted. No release was cut. `package.json` and `package-lock.json` are unchanged (the 2026.11.2 overlay used `npm install --no-save`).
- **Out of scope here:** #155 (automation account binding) and #151/#152 (shim lock lease) are owned elsewhere and are not re-examined.

### Probe side effects

The manual-compaction probe's control case is the bundled `claude-cli` backend. It passes the gate under test and continues into the host's launch path, so what happened next differs by version:

- 2026.10.10 and 2026.11.1: the host tried to start `claude`. The scratch `PATH` held no `claude`; the result was `claude: 1: exec: claude: not found`. `claude` did not start.
- 2026.11.2: the host stopped earlier with `Plugin entry is outside its captured source package` and did not try to start `claude`.

## Findings

### 1. Manual `/compact` is refused on pooled backends (BROKEN, pre-existing, filed #159)

`buildBackend` declares `ownsNativeCompaction: true` and no `manualCompaction`. Core's manual-compaction path returns a failure result for exactly that pair, before any process starts:

```
CLI backend "clawd" owns compaction but does not support manual compaction.
```

STATIC: `src/agents/embedded-agent-runner/compact.ts` lines 69 to 75 (`git grep` at each of the three tags finds the ownership check on line 69 and the refusal text on line 75) (https://github.com/openclaw/openclaw/blob/v2026.11.2/src/agents/embedded-agent-runner/compact.ts#L69-L75). The bundled backend declares the contract (https://github.com/openclaw/openclaw/blob/v2026.11.2/extensions/anthropic/cli-backend.ts#L209-L210), and the contract is public SDK surface (https://github.com/openclaw/openclaw/blob/v2026.11.2/src/plugins/cli-backend.types.ts#L572-L583). Unlike #137, the plugin can implement it.

EXEC: each published package's own `compactNativeCliSession` was called in-process, after that package's own `ensurePluginRegistryLoaded` had loaded the plugin from source, in the isolated state:

| OpenClaw | `clawd` | `claw1` | control `claude-cli` | control unknown id |
|---|---|---|---|---|
| 2026.11.2 | refused, text above | refused | passes the gate; then `Plugin entry is outside its captured source package` | `undefined` (core's own compaction) |
| 2026.11.1 | refused | refused | passes the gate; then `claude: not found` | `undefined` |
| 2026.10.10 | refused | refused | passes the gate; then `claude: not found` | `undefined` |

Not a 2026.11.2 regression. On 2026.8.1 the host function was not called; its dist carries the same three statements (the new test matches them) and its bundled backend declares the contract. A live `/compact` from a chat surface against a running gateway is UNTESTED. The #133 audit report (`2026-11-08-openclaw-2026.11.1.md`, finding 3) listed `manualCompaction` among fields that are "bundled-only, graceful when missing"; for the manual command that is not what the host does.

FIXTURE: `tests/issue-146-manual-compaction-contract.test.ts` does not call the host's compaction function. It has two kinds of check. A static source-shape match isolates the body of `compactNativeCliSession` in the installed dist and requires, exactly once and as complete consecutive statements, the ownership early return, the read of `backend.manualCompaction` and the failure return carrying the refusal text, with that text occurring nowhere else in the chunk. Runtime checks build the bundled backend (its declaration is required on every release, and its prompt builder and output validator are called) and register this plugin through its entry with two accounts and a pool, then read the declarations of `claw1`, `claw2` and the pooled `clawd` backend. 10 of 10 pass against 2026.8.1, 2026.10.10, 2026.11.1 and 2026.11.2 (`MULTI_CLAWD_OPENCLAW_DIST`). Mutations: inside the suite, four mutations of the real chunk are each rejected by the shape match (the real gate neutralised with an identical decoy in another function; the return expression changed; the two leading statements swapped; a second definition of the function); outside it, three mutated scratch dists each fail (gate rewritten so it no longer returns the refusal: both shape tests fail; bundled backend without `manualCompaction`, and module without the builder: the bundled test fails). The three "declares no manualCompaction" assertions are the ones to flip when #159 is implemented. The suite fixes nothing.

Regression scope for the fix is in #159.

### 2. What changed in 2026.11.2 on the surfaces the plugin mirrors (no break measured)

All of this section is STATIC: read from `git diff v2026.11.1 v2026.11.2` (959 files changed; https://github.com/openclaw/openclaw/compare/v2026.11.1...v2026.11.2). Line numbers are at `v2026.11.2`. Where a fixture or an executed check bears on the conclusion it is named; otherwise the conclusion is a reading of the source and has not been exercised.

- **Resolver context.** `src/plugins/cli-backend.types.ts` L271 and L278 add optional `agentId` and `controlOperation?: "compact"` to `CliBackendResolveExecutionArgsContext`; `src/agents/cli-runner/execute.ts` L483 and L507 pass them. Additive. `resolvePoolExecutionArgs` reads only `baseArgs`, `executionMode`, `hostOwnedTools` and `toolAvailability`.
- **Bundled argument normalisation moved.** `extensions/anthropic/cli-shared.ts`: `normalizeClaudeBackendConfig` (L466) no longer rewrites `args`/`resumeArgs`; `normalizeClaudeBackendArgs` (L145) now runs inside `resolveClaudeCliExecutionArgs`, at launch. The pool builds its own argv and no call to the bundled normaliser was found in `src/`, so no direct dependency was identified; whether the pool's argv should follow the bundled one for the new context fields is part of #159's scope. FIXTURE: the #136, #142 and `tool-cap` suites pass on the overlay. Not exercised live.
- **Synthetic auth.** `extensions/anthropic/provider-discovery.ts` L58 adds `nativeAuth` to the bundled provider's result. `src/agents/model-auth-availability.cli-runtime.ts` L142 lets the evaluator accept an object runtime-auth mode, but L136 returns earlier when the runtime provider and the model provider are the same id, which is the pool's case. `src/agents/model-auth-runtime-shared.ts` L62 adds `assertProviderAuthSupportsHttp`, which rejects a credential carrying `nativeAuth`; the pool's results carry none. FIXTURE: `tests/runtime-auth-wiring.test.ts`, 10 pass on the overlay. EXEC: rows 5 to 7 are identical across the three versions.
- **Catalog view.** `src/agents/model-catalog-view.ts` L303 narrows implicit native runtime selection to `runtime === "auto"`, and L356 to L357 key harness evidence on the credential source. L311 to L312 return the host evaluation unchanged when the runtime is `auto` or `openclaw`. The plugin registers no agent harness and sets no native runtime on its catalog rows (`grep` for `nativeRuntime`, `registerAgentHarness` and `agentHarness` over `src/*.ts`, which is the whole of `src/`, finds nothing), so that is the path its rows take. Not exercised against a gateway.
- **MCP grant cleanup.** `src/agents/cli-runner/prepare.ts` L1031 and `src/gateway/mcp-grant-store.ts`. The change replaces one internal revoke call with another; `src/plugins/cli-backend.types.ts` changed only by the two context fields above. Not exercised.
- **Manifest.** `extensions/anthropic/openclaw.plugin.json` is not in the diff, and the two packaged copies are byte-identical (`cmp`), so the manifest mirror (#134) needs no new fixture.

### 3. Availability and readiness are the same on all three versions (not a regression)

EXEC, isolated state, no gateway. The fixture has `claw1` as a login-directory account whose placeholder credential carries an unexpired expiry, `claw2` as a token-file account whose placeholder is not a setup-token, and the pool `clawd` over both.

- `models list --all --provider <id> --refresh --json` returns 10 rows for each of the three providers on each of the three versions. `available` is `true` for `claw1` and `clawd` and `null` for `claw2`, on all three.
- `models status --json`, with the fixture default model routed at the pool, reports three `modelRouteIssues` of kind `indeterminate` (the message field reads "Auth readiness could not be confirmed for <provider>/<model>.") and `missingProvidersInUse: []`, on all three versions.

Nothing here distinguishes 2026.11.2 from 2026.10.10. The gateway-backed state that the Control UI picker reads was not started and stays UNTESTED.

### 4. Test fragility observed once (no issue filed)

`tests/issue-137-isolated-completion-contract.test.ts` reads every `.js`/`.mjs` file at the top of the installed dist to find one sentence. The 2026.11.2 dist has 9,104 such files; 2026.8.1 has 5,852. On the overlay, the suite's first run failed one test at 7.5 s against the 5 s default timeout; the immediate re-run passed 8 of 8. The likely cause is a cold page cache combined with the idle I/O priority the audit ran at; that is an inference, not a measurement. In CI that suite runs in `build-and-test` against the pinned 2026.8.1 only; the `sdk-contract-compat` rows run only `tests/openclaw-sdk-contract.test.ts` (`.github/workflows/ci.yml`). If the suite is added to the overlay rows, narrow the scan or raise the timeout. For that reason the new test does not scan the dist: it reads the `compact-*` chunks and the package's `package.json`, and imports `extensions/anthropic/cli-backend.js`.
