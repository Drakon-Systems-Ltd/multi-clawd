# Compatibility audit: multi-clawd v2.6.5 vs OpenClaw v2026.11.1 and v2026.10.10

Issue #133. Read-only audit of the released package against the current stable OpenClaw and the previous minor. Observed on 2026-11-08 (UTC), 08:07 to 08:45.

## Scope and method

- **Audited:** `@drakon-systems/multi-clawd` 2.6.5 on npm (`gitHead` 5b378c73343032df498ab951954f8ee9d2eb5e70 = `origin/master` = tag v2.6.5). No unreleased commits.
- **Against:** OpenClaw v2026.11.1 (npm `latest`, GitHub release 2026-11-05) and v2026.10.10 (previous minor, 2026-11-03). - **Not done:** no live gateway RPC, no live model or usage call, no end-to-end turn. Those rows are marked **untested**.
- Earlier scope: #90 (v2026.10.8, claimed 2026-10-27, no findings posted) is cross-linked, not taken over. Nothing below duplicates a finding on #90.

Accidental note: one Claude CLI flag probe (`claude --append-system-prompt-file /dev/null -p hi --output-format json --bare`) ran a `-p` turn inside the fixture config dir. The fixture held no credentials and the shell carried no `ANTHROPIC*`/`CLAUDE_CODE_OAUTH*` variables; the result reported `duration_api_ms: 0`, `total_cost_usd: 0`, so no API round trip occurred. Future probes should use a flag that fails validation first (`--resume-session-at` without `--resume` does).

## Findings

### 1. The bundled catalog mirror is silently broken on OpenClaw >= 2026.9 (BROKEN)

`src/catalog-source.ts` resolves `dist/extensions/anthropic/cli-catalog.js` relative to the plugin SDK and calls `buildClaudeCliCatalogEntries()`. That module exists in 2026.8.1 and is **absent** from v2026.9.36, v2026.10.8, v2026.10.10 and v2026.11.1 (GitHub contents API, 404 at each tag; source trees contain no `cli-catalog.ts`). The bundled Anthropic plugin now discovers the Claude CLI menu at runtime (`extensions/anthropic/cli-model-discovery.ts`, `discoverClaudeCliModels`, manifest `modelCatalog.discovery: { "claude-cli": "refreshable" }`).

Fixture reproduction (`/tmp` script mirroring the resolver, `NODE_PATH` at the installed 2026.11.1):

```
{"openclaw":"2026.11.1","cliCatalogExists":false,"loadBundledCatalogIds":"IMPORT FAILED: ERR_MODULE_NOT_FOUND"}
control 2026.8.1: {"loadBundledCatalogIds":{"count":7,"sample":["claude-opus-5","claude-sonnet-5","claude-fable-5","claude-opus-4-8"]}}
```

Effect: `loadBundledCatalogIds()` returns `null`, `resolveBaseModelIds()` falls back to the static `FALLBACK_MODEL_IDS` (11 ids in `src/models.ts`; no `claude-haiku-5-5`, which the 2026.11.1 Anthropic manifest lists as its default utility model). The README's "a new subscription model shipped by OpenClaw appears on our backends automatically" and the model-currency notice (`checkModelCurrency(await resolveBaseModelIds(), ...)`, `src/index.ts`) therefore run on the static list only. Model **runs** are not broken: unknown modern `claude-*` ids still resolve through `resolveDynamicModel`. What breaks is the catalog listing/picker rows and the new-model courtesy notice.

Regression-test scope: a contract test that asserts the mirror resolves on the installed OpenClaw, or (preferred) a port to the current discovery path with a fixture `claude` that emits the native menu; and a test that the static fallback at least contains every id the bundled Anthropic manifest declares for `claude-cli`.

Filed: see the issue list at the end.

### 2. The SDK contract suite is pinned to 2026.8.1 and cannot see current drift (TEST BLIND SPOT)

`tests/openclaw-sdk-contract.test.ts` asserts `packageJson.version === "2026.8.1"` and imports two semi-internal files by path. Against the installed 2026.11.1 (same fixture script):

- `dist/extensions/anthropic/cli-shared.js` no longer exports `CLAUDE_CLI_CLEAR_ENV` (`undefined`); it moved to `cli-constants.ts`/`.js` in 2026.10.10 and 2026.11.1. The runtime list itself is unchanged: 41 variables, identical across 2026.8.1, 2026.10.10 and 2026.11.1, and multi-clawd's `CLEAR_ENV` equals it plus `CLAUDE_CONFIG_DIR`.
- `dist/extensions/anthropic/cli-catalog.js` is gone (finding 1), so "the bundled Claude catalog remains loadable" would fail.
- `cli-backend.js` still exports `buildAnthropicCliBackend` (OK).

CI runs only against the pinned devDependency, so both drifts are invisible. Regression-test scope: a second CI job (or a `fleet-remote-test` lane) that installs `openclaw@latest` into a throwaway tree and runs the contract suite with the version pin relaxed, and import paths updated to `cli-constants.js`.

### 3. Pooled backends omit `hostOwnedTools`; exec/process stay native on OpenClaw >= 2026.10 (DIVERGENCE)

Both audited versions' bundled `claude-cli` backend declares `hostOwnedTools: ["exec", "process"]` (`extensions/anthropic/cli-backend.ts`). Core (`src/agents/cli-runner/prepare-mcp.ts`, `resolveCliMcpToolOwnership`) then routes `exec`/`process` through OpenClaw's own tools for normal chat turns (host != node, no exact cap, `selectable` + `execution-args` + `resolveExecutionArgs`), and the bundled `resolveClaudeCliExecutionArgs` (`extensions/anthropic/cli-shared.ts`) appends `Bash` to `--disallowedTools` when `hostOwnedTools` includes `exec`; `execute-plugin.ts` denies the native equivalent ("Use OpenClaw exec; its native equivalent is unavailable."). The field is absent from the pinned 2026.8.1.

multi-clawd's `buildBackend` declares none of `hostOwnedTools`, and `resolvePoolExecutionArgs` (`src/tool-cap.ts`) only handles `toolAvailability`. So on 2026.10.10 and 2026.11.1 a chat turn on `clawd/*` or `claw<N>/*` lets Claude Code's own `Bash` run under the Claude permission mode that `permissionModeArgs(execMode)` derives, while the same turn on `claude-cli/*` runs commands through OpenClaw's `exec` tool with its approval/allowlist policy. Nothing fails closed; this is a silent behavioural and policy difference from the "mirror the bundled claude-cli backend" contract in `src/index.ts`. Also absent on the pool (bundled-only, graceful when missing): `projectNativeToolAuthority`, `transformSystemPrompt`, `manualCompaction`, `subscriptionAuthDispatch`, and the 2026.11.1 opt-in `resolveManagedNativeTools`.

Regression-test scope: a fixture test that, with `hostOwnedTools: ["exec","process"]` declared, the pool's execution args carry `Bash` in `--disallowedTools` for a normal turn and still strip it for exact caps; plus a docs note on which execution path commands take on each backend.

### 4. Isolated completions are refused on pooled backends (PRE-EXISTING GAP, upstream-private contract)

`src/agents/cli-runner/prepare.ts` (both versions, and the 2026.8.1 dist) throws `CLI backend "<id>" does not support isolated completion; OpenClaw did not start the run.` unless `prepareExecution` returns `isolatedCompletionEnforced: true`. That flag is not in the SDK's `CliBackendPreparedExecution` type (only `toolAvailabilityEnforced` is); the bundled backend sets it from `isolatedCompletionPrompt`, which core passes with the comment "Keep it private so exact isolated inference does not expand the SDK." multi-clawd never sets it. Any isolated completion (`src/agents/isolated-completion.ts`: prompt-only, tool-less side inference) routed to a pooled provider therefore fails. The gateway log on this box shows 0 occurrences of that message on 2026-11-07 and 2026-11-08, so the default routing does not currently send isolated completions to the pool here. Verified from source, **not observed live**, and not a regression between the two audited versions.

Regression-test scope: a fixture test of `prepareExecution` with the private `isolatedCompletion*` context fields present, asserting either the flag is set with the side-question projection applied, or an explicit documented limitation. A clean fix needs the SDK to expose the contract; track upstream.

### 5. Node 22 is unsupported by both audited OpenClaw versions (DOCS/CI DRIFT, not a break)

| | Node engines |
|---|---|
| openclaw 2026.8.1 (pinned devDependency) | `>=22.22.3 <23 \|\| >=24.15.0 <25 \|\| >=25.9.0` |
| openclaw 2026.10.10 | `>=24.16.0 <25 \|\| >=26.1.0` |
| openclaw 2026.11.1 | `>=24.16.0 <25 \|\| >=26.1.0` (docs: 24.22.1+/26.12.1+ recommended; Node 22 "Unsupported since the 24.16.0/26.1.0 floor") |

multi-clawd declares no `engines`, CI runs Node 22 and 24, and `PUBLISHING.md` describes the Node 22 lane. A plugin loaded by a current gateway necessarily runs on Node 24 or 26; only the standalone `multi-clawd` CLI and the Hermes commands could still meet Node 22. Recommendation (docs): state "Node 24.16+ or 26.1+ for the gateway/plugin; Node 22 only for the standalone CLI", and consider adding Node 26 to CI. No issue filed: nothing is broken.

## Verified OK (by source, both versions)

- **SDK subpaths:** `openclaw/plugin-sdk/plugin-entry` (`definePluginEntry`, `OpenClawPluginApi`, `ProviderPlugin`, `ProviderRuntimeModel`), `openclaw/plugin-sdk/agent-runtime` (`ModelCatalogEntry`), `openclaw/plugin-sdk/secret-ref-runtime` (`resolveSecretRefValues`) all exported and mapped in `package.json#exports`. The deprecated subpaths the plugin avoids still exist but are not needed.
- **CLI backend config:** every field multi-clawd sets is typed in `src/plugins/cli-backend.types.ts` with the same enum values (`nativeToolMode: "selectable"`, `toolAvailabilityEnforcement: "execution-args"`, `sideQuestionToolMode: "disabled"`, `bundleMcpMode: "claude-config-file"`, `jsonlDialect: "claude-stream-json"`, `freshSessionRecovery: "invalidated-only"`, `imagePathScope: "workspace"`, `systemPromptWhen: "always"`, `sessionMode: "always"`, `reseedFromRawTranscriptWhenUncompacted`, `reliability.watchdog`, `serialize`, `runtimeArtifact` shape `bundled-package-tree`/`command`/`nativeExecutableNames`). `prepareExecution` context still carries `modelId`, `agentDir`, `workspaceDir`, `executionMode`. The optional `exactToolAvailabilityVersionPolicy` is unused by the bundled backend too.
- **Registration modes:** `cli-metadata` and `setup-only` are still the only modes with an unavailable (throwing) runtime (`src/plugins/captured-registration.ts`); `isRuntimelessRegistration` matches.
- **Hooks:** `heartbeat_prompt_contribution` and `before_model_resolve` remain registered hook names.
- **Provider availability path:** `prepared-model-runtime.facts.ts` is byte-identical between 2026.10.10 and 2026.11.1; CLI-backend owners are "authoritative synthetic auth" refs; `addSyntheticCredential` accepts any trimmed `apiKey`, and `oauth:` remains a recognised non-secret marker prefix (`src/agents/model-auth-markers.ts`). The #39 fix path is unchanged. 2026.11.1 adds a `cli-execution-auth` branch for bundled strict-profile backends only. Live picker state **not re-verified**.
- **CLI commands shelled out to** (`models auth list|login|paste-token|order get|set`, `models status --probe --json`, `plugins inspect --json`, `plugins install clawhub:... --pin --force`, `plugins update --all`, `gateway restart`): present in both source trees; `--help` of the installed 2026.11.1 CLI under a fixture `HOME` confirms each.
- **Manifest:** `modelCatalog.runtimeAugment: true` is still honoured (`src/plugins/providers.ts`); `compat.minGatewayVersion` is read by the ClawHub installer; `activation.onStartup`, `cliBackends`, `providers` validated.
- **Claude CLI 2.1.319** (local, fixture config dir): `--resume-session-at` is recognised (fails validation without `--resume`, unlike an unknown flag), `--append-system-prompt-file` accepted; the bundled backend uses the same flags.
- **npm 10.9.10 and npm 11.19.1:** `npm ci --dry-run --ignore-scripts` against the committed lockfile succeeds for both (443 and 376 packages respectively); #48's `edgesOut` crash does not reproduce at resolution level. The CI comment "npm 10 crashes" is stale; full install **untested** here.
