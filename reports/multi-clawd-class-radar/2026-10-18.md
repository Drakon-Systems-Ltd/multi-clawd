# multi-clawd class radar: 2026-10-18

First weekly public-source radar (issue #49). Sources were observed on **2026-10-19 (UTC)**. The file is named for the issue date.

## Method and limits

- Sources are public GitHub READMEs, fetched through the GitHub API, plus public OpenClaw docs and search snippets. Repo metadata (last push, stars, licence) comes from `GET /repos/{owner}/{repo}` on the observation date.
- Every capability below is **what the project's README says**, not something that was verified. Nothing was installed or run, no credentials were used, and no provider calls were made.
- multi-clawd facts come from this repo at `1dffb8f` (`master`, v2.1.3 plus #53). Each one cites a file and line.
- Gap rule: a capability is filed as a class gap only if at least two independent public tools document it, multi-clawd does not have it, and no existing multi-clawd issue covers it.

## The class

There are two families of tool that put more than one Claude subscription behind an agent.

1. **OpenClaw-native.** On ClawHub, multi-clawd is the only multi-account Claude plugin under the `multi-account` and `failover` topics (https://clawhub.ai/plugins?topic=multi-account, https://clawhub.ai/plugins?topic=failover, as seen in search snippets). OpenClaw core also rotates its own `anthropic` auth profiles on rate-limit errors, keeps a per-session auth pin, and supports model-scoped cooldowns (https://docs.openclaw.ai/concepts/model-failover, https://docs.openclaw.ai/gateway/authentication). That covers the direct API route only, not the `claude` CLI backend that multi-clawd pools.
2. **Standalone, for Claude Code.** These are local MITM/base-URL proxies, credential switchers and launch wrappers.
